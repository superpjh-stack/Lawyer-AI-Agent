## 1. Overview

### 1.1 Purpose

LexAgent v0.8까지 구현된 기본 AI 채팅과 국가법령정보 API 연동 위에, **RAG (Retrieval-Augmented Generation)** 기반의 고급 법률 AI 기능 5종을 추가하여 변호사의 실무 생산성을 비약적으로 향상시킨다.

### 1.2 Background

- 현재 AI 채팅은 GPT-4o 직접 호출 방식으로, 법무법인 고유 문서/판례에 대한 맥락 없이 일반적 답변만 생성
- `orchestrator.ts`의 `search_documents`, `analyze_document` 도구가 mock 구현 상태
- v0.7 설계 문서 (`v0.7-rag-architecture.md`)에서 LangChain.js + pgvector 아키텍처를 설계했으나 미구현
- 법무법인은 과거 소장, 준비서면, 계약서 등 축적된 문서 자산이 있으나 활용 불가
- 판례 검색은 키워드 기반만 가능하고, 시맨틱(의미) 검색이 불가

### 1.3 Related Documents

- v0.7 RAG Architecture: `docs/02-design/v0.7-rag-architecture.md`
- v0.8 Case Law Search: `docs/02-design/v0.8-case-law-search.md`
- Current Schema: `prisma/schema.prisma`

## 2. Feature Breakdown

### Feature Group A (PM-A 담당)

#### Feature 1: 문서 Q&A

사용자가 업로드한 문서(PDF, DOCX, TXT)에 대해 자연어로 질문하고 정확한 답변을 받는 기능.

**User Stories:**
| ID | As a... | I want to... | So that... |
|----|---------|-------------|-----------|
| US-A01 | 변호사 | 계약서 PDF를 업로드하고 "갱신 조건이 뭔가요?" 질문 | 전체 문서를 읽지 않고 핵심 조항을 빠르게 파악 |
| US-A02 | 변호사 | 여러 문서를 업로드하고 교차 질의 | 관련 문서간 조항 비교/분석 가능 |
| US-A03 | 변호사 | 답변에 출처 표시 확인 | 어떤 문서의 몇 페이지에서 나온 답인지 신뢰할 수 있음 |
| US-A04 | 변호사 | 이전에 업로드한 문서를 지식베이스에서 삭제 | 불필요한 데이터를 정리 |

**Acceptance Criteria:**
- [ ] PDF, DOCX, TXT 파일 업로드 및 텍스트 추출
- [ ] 문서를 1000자 단위 청크로 분할 (200자 오버랩)
- [ ] pgvector에 임베딩 저장 (text-embedding-3-small, 1536차원)
- [ ] 자연어 질문 시 유사도 기반 top-5 청크 검색
- [ ] GPT-4o가 검색된 컨텍스트 기반으로 답변 생성
- [ ] 답변에 [출처: 문서명, 청크번호] 형식으로 출처 표시
- [ ] 임베딩 상태 표시 (처리중/완료/실패)

#### Feature 4: 계약서 리스크 분석

업로드된 계약서를 AI가 즉시 분석하여 불리한 조항, 누락 조항, 법적 리스크를 탐지하는 기능.

**User Stories:**
| ID | As a... | I want to... | So that... |
|----|---------|-------------|-----------|
| US-A05 | 변호사 | 계약서를 업로드하면 즉시 리스크 분석 | 수동 검토 시간 대폭 단축 |
| US-A06 | 변호사 | 조항별 위험도(높음/중간/낮음) 확인 | 우선 검토 대상을 빠르게 식별 |
| US-A07 | 변호사 | 유사 계약서의 표준 조항과 비교 | 누락된 보호 조항 발견 |
| US-A08 | 변호사 | 리스크 분석 결과를 PDF로 저장 | 고객에게 보고서로 전달 |

**Acceptance Criteria:**
- [ ] 계약서 업로드 시 자동 리스크 분석 트리거 옵션
- [ ] 조항별 위험도 분류 (High / Medium / Low)
- [ ] 불리한 조항 설명 + 수정 권고사항 제시
- [ ] 누락 조항 체크리스트 (예: 분쟁해결 조항, 손해배상 제한 등)
- [ ] 지식베이스의 유사 계약서 참조하여 비교 분석
- [ ] 분석 결과 JSON + 렌더링된 UI 카드 형태
- [ ] 기존 mock `analyze_document` 도구를 실제 구현으로 대체

### Feature Group B (PM-B 담당)

#### Feature 2: 판례 시맨틱 검색

기존 키워드 기반 판례 검색에 벡터 유사도 검색을 결합한 하이브리드 검색.

**User Stories:**
| ID | As a... | I want to... | So that... |
|----|---------|-------------|-----------|
| US-B01 | 변호사 | "임대인이 계약해지를 일방적으로 통보한 사건" 같은 자연어로 판례 검색 | 정확한 법률 용어를 몰라도 관련 판례를 찾을 수 있음 |
| US-B02 | 변호사 | 키워드 + 시맨틱 결과를 함께 보기 | 누락 없이 포괄적 검색 가능 |
| US-B03 | 변호사 | 북마크한 판례를 시맨틱 검색 대상에 포함 | 자주 참조하는 판례가 검색에 반영 |
| US-B04 | 변호사 | 유사 판례 추천 | 현재 사건과 관련된 판례를 자동 발견 |

**Acceptance Criteria:**
- [ ] 기존 국가법령정보 API BM25 검색 유지
- [ ] pgvector 기반 시맨틱 검색 추가 (CaseLawBookmark embedding 활용)
- [ ] Hybrid Search: BM25 결과 + Vector 결과를 RRF (Reciprocal Rank Fusion) 으로 병합
- [ ] 검색 UI에 "키워드" / "시맨틱" / "하이브리드" 모드 선택
- [ ] 북마크 시 자동 임베딩 생성 (aiSummary 기반)
- [ ] 유사도 점수 표시

#### Feature 3: Multi-step Legal Agent

판례검색 -> 분석 -> 문서초안 생성을 자동으로 연결하는 다단계 AI 에이전트.

**User Stories:**
| ID | As a... | I want to... | So that... |
|----|---------|-------------|-----------|
| US-B05 | 변호사 | "이 사건에 맞는 소장을 작성해줘"라고 하면 자동으로 판례검색 -> 분석 -> 초안 생성 | 반복적인 단계별 작업을 자동화 |
| US-B06 | 변호사 | 각 단계별 중간 결과 확인 | AI의 판단 과정을 투명하게 이해 |
| US-B07 | 변호사 | 중간 단계에서 수정 입력 후 재진행 | AI 판단을 보완하여 더 정확한 결과 도출 |
| US-B08 | 변호사 | 에이전트 실행 이력 저장 | 나중에 동일 유형 사건에 재활용 |

**Acceptance Criteria:**
- [ ] LangChain AgentExecutor 기반 multi-step 에이전트
- [ ] 도구 체인: search_cases -> analyze_relevance -> draft_document
- [ ] 각 단계별 SSE 스트리밍 (단계 시작/진행/완료 이벤트)
- [ ] 중간 결과 UI 표시 (스텝 인디케이터)
- [ ] 사용자 개입 지점 (중간 단계 후 확인/수정)
- [ ] 에이전트 실행 이력 DB 저장

#### Feature 5: 법무법인 내부 지식베이스

과거 소장, 준비서면, 법률의견서 등 법무법인의 축적된 문서를 임베딩하여 AI가 참조할 수 있는 지식베이스.

**User Stories:**
| ID | As a... | I want to... | So that... |
|----|---------|-------------|-----------|
| US-B09 | 관리자 | 법무법인 공용 문서를 일괄 업로드 | 모든 변호사가 참조 가능한 지식베이스 구축 |
| US-B10 | 변호사 | 개인 문서를 지식베이스에 추가 | 나만의 스타일/전문분야 문서 참조 |
| US-B11 | 변호사 | 지식베이스에서 유사 문서 검색 | 이전 사건의 서면 양식을 재활용 |
| US-B12 | 관리자 | 지식베이스 통계 (문서 수, 청크 수, 분야별 분포) 확인 | 지식베이스 현황 파악 |

**Acceptance Criteria:**
- [ ] 일괄 문서 업로드 (drag & drop, 최대 20개)
- [ ] 문서별 메타데이터 태깅 (docType, practiceArea)
- [ ] Per-lawyer 개인 + 공용(shared) 지식 분리
- [ ] 지식베이스 관리 UI (목록, 삭제, 재임베딩)
- [ ] 지식베이스 통계 대시보드

## 6. Risks and Mitigation

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| pgvector 성능 저하 (대량 벡터) | High | Low | IVFFlat 인덱스 + lists=100, 필요시 HNSW 전환 |
| OpenAI API 비용 초과 | Medium | Medium | 임베딩 캐시, batch 처리, 비용 모니터링 |
| 한국어 임베딩 품질 | High | Medium | text-embedding-3-small 한국어 테스트, 필요시 large 전환 |
| LangChain.js 버전 호환 | Medium | Low | @langchain/core 0.3.x 고정, lock file |
| 대용량 PDF 텍스트 추출 실패 | Medium | Medium | pdf-parse 라이브러리 + fallback 처리 |
| DOCX 복잡한 서식 손실 | Low | High | mammoth.js 사용, 서식보다 텍스트 우선 |

| Decision | Options | Selected | Rationale |
