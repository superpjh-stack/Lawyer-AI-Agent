## 1. Overview

### 1.1 Design Goals

1. 기존 LexAgent UI 패턴(sidebar, stat-card, page-header 등) 일관성 유지
2. RAG 기능이 기존 채팅/자문/문서 화면에 자연스럽게 통합
3. 모바일 반응형 (md:768, lg:1024 브레이크포인트 활용)
4. 한국어 UI, 간결한 레이블

### 1.2 Affected Pages

| Page | Change Type | Description |
|------|------------|-------------|
| `/chat` | Modified | RAG 토글, 출처 표시, 에이전트 스텝 |
| `/advisory` | Modified | RAG 컨텍스트 선택 |
| `/research/case-law` | Modified | 검색 모드 선택 (키워드/시맨틱/하이브리드) |
| `/documents` | Modified | 임베딩 상태 표시, 자동 임베딩 옵션 |
| `/settings/knowledge` | New | 지식베이스 관리 |
| `/documents/[id]` | Modified | 리스크 분석 결과 표시 |

### 3.1 `/chat` -- RAG 통합

**변경 사항:**

```

```

- 토글 시 `/api/chat`에 `ragEnabled` 파라미터 전달
- 기본값: ON

#### 3.1.2 Source Citations Panel

AI 응답 하단에 참조 문서 표시:

```
┌──────────────────────────────────────────────────┐
│  [AI 응답 텍스트...]                               │
│                                                    │
│  ┌──────────────────────────────────────────────┐  │
│  │  참조 문서 (3건)                    [접기 ^]  │  │
│  │  ┌────────────────────────────────────────┐  │  │
│  │  │ 1. 매매계약서 (청크 4/12) | 유사도 89% │  │  │
│  │  │ 2. 민법 제544조          | 유사도 85% │  │  │
│  │  │ 3. 대법원 2020다12345    | 유사도 82% │  │  │
│  │  └────────────────────────────────────────┘  │  │
│  └──────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

- `sources` SSE 이벤트 수신 시 렌더링
- 기본 접혀있음, 클릭 시 펼침
- 각 출처 클릭 시 해당 문서 상세 페이지로 이동

#### 3.1.3 Agent Step Indicator

Multi-step 에이전트 실행 시:

```
┌──────────────────────────────────────────────────┐
│  ┌────────────────────────────────────────────┐   │
│  │  [1] 요청 분석   [2] 판례 검색  [3] 초안   │   │
│  │   (v)완료         (...)진행중    (-)대기    │   │
│  └────────────────────────────────────────────┘   │
│                                                    │
│  [판례 검색 중... 관련 판례 3건 발견]               │
│  [로딩 스피너]                                     │
└──────────────────────────────────────────────────┘
```

- `agent_step` SSE 이벤트로 업데이트
- 각 스텝: 대기(grey) -> 진행(blue animate-pulse) -> 완료(green checkmark) -> 실패(red x)
- `agent_pause` 시 "계속 진행하시겠습니까?" 확인 버튼 표시

## 5. Document Page Enhancements

### 5.1 `/documents` -- 임베딩 상태 표시

문서 목록 테이블에 임베딩 상태 칼럼 추가:

```
| 파일명 | 유형 | 크기 | 임베딩 | 등록일 |
|--------|------|------|--------|--------|
| 계약서.pdf | 계약서 | 2.1MB | [완료] | 03.09 |
| 소장.docx | 소장 | 1.5MB | [처리중...] | 03.09 |
| 참고.txt | 기타 | 0.3MB | [-] | 03.08 |
```

상태 뱃지:
- `null`: `-` (회색, 임베딩 안 됨)
- `processing`: `처리중` (파란색, animate-pulse)
- `completed`: `완료` (초록색)
- `failed`: `실패` (빨간색, 재시도 버튼)

## 10. User Flow Diagrams

### 10.1 Document Q&A Flow

```
[문서 업로드] -> [임베딩 처리] -> [AI 채팅에서 질문]
                                       |
                                  [RAG 검색]
                                       |
                                  [답변 + 출처 표시]
```

### 10.2 Contract Risk Analysis Flow

```
[문서 상세 페이지] -> [리스크 분석 실행 버튼]
                          |
                     [분석 진행 (로딩)]
                          |
                     [결과 표시: 조항별 리스크 + 누락 조항]
```

### 10.3 Multi-step Agent Flow

```
[AI 채팅에서 복잡한 요청] -> [에이전트 시작]
                                 |
                            [Step 1: 분석] -> [완료]
                                 |
                            [Step 2: 검색] -> [완료 + 중간결과]
                                 |
                            [사용자 확인/수정]
                                 |
                            [Step 3: 초안] -> [완료 + 출처]
```

### 10.4 Knowledge Base Management Flow

```
[설정 > 지식베이스] -> [통계 확인]
        |
   [문서 업로드 (drag & drop)]
        |
   [메타데이터 태깅 (유형/분야/공용)]
        |
   [임베딩 시작]
        |
   [목록에서 확인/삭제]
```
