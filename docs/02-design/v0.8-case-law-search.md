# v0.8 Design: 판례 원문 검색 (Case Law Search)

## 1. 아키텍처 개요

```
[Client Page]
  |
  |-- GET /api/research/case-law?q=키워드&type=keyword|semantic&page=1
  |     |
  |     |-- keyword: law-api.ts -> 국가법령정보 API (외부)
  |     |-- semantic: pgvector similarity search (내부 DB)
  |     |-- fallback: Mock 데이터 반환
  |
  |-- GET /api/research/case-law/[id]
  |     |-- law-api.ts -> 판례 원문 상세 조회
  |     |-- openai -> AI 요약 생성
  |
  |-- GET/POST /api/research/bookmarks
  |     |-- Prisma CaseLawBookmark CRUD
  |
  |-- DELETE /api/research/bookmarks/[id]
```

## 2. DB 스키마

### CaseLawBookmark 모델 (Prisma)

```prisma
model CaseLawBookmark {
  id              String   @id @default(cuid())
  userId          String
  caseId          String?          // 연결된 사건 (optional)
  serialNumber    String           // 국가법령정보 판례 일련번호
  caseNumber      String           // 사건번호 (예: 2023다12345)
  caseName        String           // 판례 제목
  courtName       String           // 법원명
  judgmentDate    String           // 선고일자
  caseType        String?          // 사건종류 (민사, 형사 등)
  aiSummary       String?          // AI 요약 캐시
  embedding       Unsupported("vector(1536)")?  // pgvector 임베딩
  createdAt       DateTime @default(now())
  user            User     @relation(fields: [userId], references: [id])
  case            Case?    @relation(fields: [caseId], references: [id])
  @@unique([userId, serialNumber])
  @@index([userId])
  @@index([caseId])
}
```

User, Case 모델에 relation 추가 필요.

## 3. API 설계

### 3.1 GET /api/research/case-law

키워드 또는 시맨틱 검색.

**Query Parameters:**
| Param | Type | Required | Description |
|-------|------|----------|-------------|
| q | string | Yes | 검색어 |
| type | "keyword" \| "semantic" | No (default: keyword) | 검색 타입 |
| page | number | No (default: 1) | 페이지 |
| pageSize | number | No (default: 20) | 페이지 크기 |

**Response:**
```json
{
  "data": {
    "items": [
      {
        "serialNumber": "12345",
        "caseNumber": "2023다12345",
        "caseName": "손해배상(기)",
        "courtName": "대법원",
        "judgmentDate": "2023-01-15",
        "caseType": "민사",
        "snippet": "..."
      }
    ],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}
```

### 3.2 GET /api/research/case-law/[id]

판례 원문 + AI 요약.

**Path:** `id` = 판례 일련번호 (serialNumber)

**Response:**
```json
{
  "data": {
    "serialNumber": "12345",
    "caseNumber": "2023다12345",
    "caseName": "손해배상(기)",
    "courtName": "대법원",
    "judgmentDate": "2023-01-15",
    "caseType": "민사",
    "content": "판결 전문 텍스트...",
    "aiSummary": "AI 요약 텍스트...",
    "isBookmarked": false
  }
}
```

### 3.3 GET /api/research/bookmarks

북마크 목록 조회.

**Query Parameters:**
| Param | Type | Description |
|-------|------|-------------|
| caseId | string? | 특정 사건에 연결된 북마크만 |
| page | number | 페이지 |

### 3.4 POST /api/research/bookmarks

북마크 저장.

**Body:**
```json
{
  "serialNumber": "12345",
  "caseNumber": "2023다12345",
  "caseName": "손해배상(기)",
  "courtName": "대법원",
```

### 3.5 DELETE /api/research/bookmarks/[id]

북마크 삭제.

## 4. 국가법령정보 API 연동

### 엔드포인트
- 판례 검색: `https://www.law.go.kr/DRF/lawSearch.do?target=prec&query={keyword}&type=XML`
- 판례 상세: `https://www.law.go.kr/DRF/lawService.do?target=prec&ID={serialNumber}&type=XML`
- 인증: OC (인증키) 파라미터

### law-api.ts 설계
```typescript
// 환경변수: KOREA_LAW_API_KEY
// Fallback: API key 미설정 시 Mock 데이터 반환

export async function searchCaseLaw(query: string, page: number): Promise<CaseLawSearchResult>
export async function getCaseLawDetail(serialNumber: string): Promise<CaseLawDetail>
```

### Mock 데이터 전략
- `KOREA_LAW_API_KEY` 환경변수가 없거나 빈 문자열인 경우
- API 호출 실패 시 (네트워크 에러, 500 등)
- 법률 도메인에 적합한 한국어 Mock 데이터 5건 반환

## 5. pgvector 시맨틱 검색

### 마이그레이션
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 임베딩 저장
- 북마크 저장 시 판례 내용을 text-embedding-3-small로 임베딩
- CaseLawBookmark.embedding 컬럼에 저장
- Raw SQL로 cosine similarity 검색

### 시맨틱 검색 쿼리
```sql
SELECT *, 1 - (embedding <=> $1::vector) as similarity
FROM "CaseLawBookmark"
WHERE "userId" = $2
ORDER BY embedding <=> $1::vector
LIMIT 10;
```

## 6. UI 설계

### 6.1 /research/case-law (목록)
- 검색바 (키워드 입력 + 검색 버튼)
- 검색 타입 토글: 키워드 / 시맨틱 (시맨틱은 북마크 내 검색)
- 결과 카드 리스트 (판례명, 법원, 사건번호, 선고일, snippet)
- 페이지네이션
- 모바일: 카드 풀 width, 텍스트 축소

### 6.2 /research/case-law/[id] (상세)
- 두 컬럼 레이아웃: 좌=원문, 우=AI요약 (lg 이상)
- 모바일: 탭 전환 (원문 / AI요약) -- MobileTabs 활용
- 북마크 버튼 (토글)
- 사건 연결 드롭다운 (optional)

### 6.3 사이드바 변경
- navItems의 "법률 리서치"를 sub-items로 분리하지 않음
- 대신 /research 페이지 내에서 탭으로 분기
- 연구 페이지 탭: "판례 요약검색" | "판례 원문 검색" | "법령 검색"
